The project

Aura Logbook is a full-stack mood-reflection journal that helps people record emotions, revisit personal history, and explore patterns over time. Users can choose a reflective pathway—Mindful Living, Astrology & Energy, or Faith & Religion—so journaling can align with their beliefs and perspective. They can personalize a profile and explore dashboard context such as mood trends, zodiac-based reflections, and current weather. It is a reflection tool—not a diagnostic or treatment tool.

My focus: connecting a typed frontend to a .NET API, organizing application responsibilities, and handling authenticated workflows.

A path from check-in to reflection

The reviewed source supports these stages across the UI and API. This describes implemented routes and operations; it is not a claim that every path has passed end-to-end testing.

  2. 02

  3. 03

  4. 04

The dashboard also requests current weather from Open-Meteo (Atlanta is the configured location). Weather is contextual information—not a field saved with a mood entry.

Inside the implementation

Frontend foundation

The manifest specifies React 19.1, TypeScript 5.8, Material UI 7.1, Joy UI 5 beta, Redux Toolkit 2.8 with RTK Query, React Router 7.6, Axios 1.10, and Recharts 2.15. The app includes session restoration, loading feedback, and expired-session notifications.

Backend responsibilities

The API targets .NET 9. Its mood controller delegates work to injected mood and statistics services; authorized actions cover mood-entry creation, retrieval, editing, deletion, and dashboard queries. JSON file repositories are active. SQLite and Dapper appear in the project dependencies but are not wired into persistence.

Development support

A debug-only endpoint generates sample entries to support development. Frontend tests use Vitest and Testing Library; API tests use xUnit and Moq. Their presence shows test coverage exists, not that the suites have been run or passed for this portfolio update. Setup and environment configuration are documented in the repository.

What this demonstrates

This project demonstrates full-stack product development across authenticated user workflows, API design, layered backend architecture, frontend state management, external API integration, data visualization, and automated testing.

Current state & next steps

In development. The inspected source currently stores user, mood, and zodiac-insight data in JSON files. As the project expands, I plan to move application data to a small database such as SQLite. SQLite and Dapper are declared dependencies, but the migration is future work—the app does not currently persist records in SQLite.

The next step is to complete end-to-end verification of the sign-in, journaling, history, and dashboard paths, then document the UI/API integration with fictional demo data.
