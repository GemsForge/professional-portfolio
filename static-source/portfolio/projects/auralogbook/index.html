The project

Aura Logbook is a mobile-first journal for what you feel and believe. It gives people a private place to name emotions, write what is on their mind, and revisit those reflections over time; a responsive desktop companion brings the same flow to a larger screen. People can shape prompts through Mindful Living, Astrology & Energy, or Faith & Religion, choosing the perspective that fits them. Mood history and insights help them notice patterns, while light, dark, and system appearance choices make the journal feel personal. Aura is a reflection tool—not a diagnostic or treatment tool.

My focus: shaping the phone-first experience, its responsive desktop companion, and the relational API workflows behind the journal.

Music for the moment

The optional Spotify connection brings a person’s current listening context into the dashboard: the track that is playing, plus a browsable shelf of playlists from their Spotify account. Playlist links and the now-playing link continue in Spotify, so Aura can sit alongside someone’s listening without becoming a music player. Inside the implementation

Mobile and web clients

The product is designed for phone use first. The React Native/Expo shell defines native Today, Log, Journal, and Profile destinations. The current paired screenshots come from the responsive React 19/TypeScript web client, which uses Material UI, Joy UI, Redux Toolkit with RTK Query, React Router, Axios, and Recharts to support phone and desktop layouts.

Backend responsibilities

The API targets .NET 9. Controllers delegate to injected services, while user-scoped routes support authentication, mood entries, reflections, insights, and private media, and an optional Spotify connection for currently playing tracks and playlists. SQLite persistence is implemented through Dapper repositories and versioned SQL migrations in Development and FIT/Staging. Database-backed reference definitions and presentation settings support pathway-specific prompts, moods, colors, and themes.

Spotify account connection

Spotify linking uses OAuth Authorization Code with PKCE. The API keeps access and refresh tokens encrypted, then returns only playback and playlist metadata to the signed-in Aura user. The dashboard card handles connection, disconnection, empty playback, loading, and recovery states; playlist cards link out to Spotify, where audio playback stays.

Development support

A debug-only endpoint generates sample entries to support development. Frontend tests use Vitest and Testing Library; API tests use xUnit and Moq. Their presence shows test coverage exists, not that the suites have been run or passed for this portfolio update. Setup and environment configuration are documented in the repository.

What this demonstrates

This project demonstrates mobile-first product design, a native navigation shell, responsive web delivery, SQLite/Dapper persistence in Development and FIT/Staging, authenticated journal workflows, database-backed personalization, private media handling, a delegated Spotify integration with encrypted credentials, data visualization, and layered API architecture.
